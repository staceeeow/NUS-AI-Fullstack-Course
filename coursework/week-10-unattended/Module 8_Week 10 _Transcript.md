## Video 3: Controlled vs. Uncontrolled Components

Welcome to a lecture on "Controlled vs. Uncontrolled Components". Here are the learning objective. By the end of this lecture, you should understand the two types of components in React and be able to differentiate between Controlled and Uncontrolled components.

In React, components are rendered according to the state or prop. The two main kinds of components when dealing with states are controlled components and uncontrolled components. Control components render the user interface based on the state values. At any given time, the state values dictate the UI. For example, consider a textbox whose value is bounded to a state variable. When you type into the textbox, it will update the state value for each onChange event. And since the textbox is bounded to the state variable, this will effectively update the value of the textbox.

Controlled components are generally recommended because the state serves as the single source of truth. This makes it easier to test your components since you can always verify the UI by checking the state values. When the state values are correct, you can be confident that the UI will be correct. Uncontrolled components, on the other hand, update the state at specific events point, such as the result of an onClick event. In this case, the DOM acts as the source of truth. Which is not ideal. Consequently, for unit testing, you can't rely solely on checking the changes in the state values. You will also have to check the DOM values, whether they are rendered properly.

Let's take a look at an example of an uncontrolled component. In this scenario, the DOM itself maintain the state until a specific event triggers a state update.

Specifically, when a user types a name into a text box, what the user type in is reflected in the text box because that is the default behaviour of text boxes. However, each keystroke is not captured into a React state variable. Instead, the state variable is only updated when the user press the update name button. The issue with this approach is that the UI is not just defined by the state variable but also defined by the contents of the DOM. For example, the page can show Hello John, but the textbook might contain another name that is not John, since the state variable is not modified yet.

To summarise, we have covered two types of components in React, controlled components and uncontrolled components. We have discussed the key differences between them. Controlled components use the state as the source of truth. And uncontrolled components relies on the DOM. Understanding these key differences will help you make informed decision when building your React application. As far as possible, it's always preferred to use the controlled component approach.

Let's start with the concept of Single-Page Application, or SPA. Frontend frameworks like Angular, React, and VueJs allow us to create SPAs, where there is technically only one page. However, often we want to create the effect of multiple pages, similar to traditional websites. To provide the illusion of multiple pages, the solution lies in dynamically switching the UI components based on the user navigation path. The main benefit of SPAs include no full page reloads, leading to a smoother user experience and reduced bandwidth consumption.

Frontend routing follows a similar idea to backend routing but is implemented on the client side. The client scripts will determine which component to render based on the URL path. The 2 common routing mechanism in React are HashHistory and BrowserHistory. When working with HashHistory, URLs look like the following. Specifically, the URL contains a hash symbol followed by the path. The main page will then display the relevant components meant for that path. On the other hand, when using BrowserHistory, URLs resemble those used in backend routing. Note that even though the URL contains the full path, the server will access the main page and the script in the main page will then interpret the path from the URL and display the relevant component.

To achieve this routing capability, we install a third-party library known as React Router. This is a command to install the library into your React app. To set up React Router, you need to first wrap your main components within either the HashRouter or BrowserRouter component. Specifically, within index.js, we will wrap our App component within one of these Router components.
