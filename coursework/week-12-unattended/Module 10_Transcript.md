## Video 2: Backend Software Engineering with JavaScript and Python

In this video, I will demystify the differences between backend and frontend software engineering with you. I will also explain the difference between client-side rendering and server-side rendering web application. Modern software applications manifest in many form factors such as desktop, web, and mobile applications. Web applications are among the most common ones.

Web applications run within a web browser and are developed with standard-based technologies such as Hypertext Markup Language or HTML, and Cascading Style Sheets or CSS. Examples of web applications include digital commerce websites, communication tools and even productivity software. Web applications are increasingly popular as compared to desktop applications for at least three reasons. First, they are cross-platform compatible and easily run across operating systems and devices. Second, they impose minimal requirements on the computer of end-users. Finally, they simplify deployment, installation, and maintenance.

Web applications are typically structured using the client-server architecture. The server contains the resources to be shared with multiple users or clients, in this case the web pages. The client, in this case a web browser, will request the required web pages from the server and display them to the user. This infographic shows the client-server architecture of general software applications. Development tasks associated with the data tier and logic tier of an application are typically known as backend development. Those that are associated with the presentation tier are known as frontend development. The data tier and logic tier typically run on the server whereas the presentation tier runs on the client. However, for web applications, the code for the presentation tier, which are the code for generating the HTML content, can be executed on either the server or client. The former is known as server-side HTML rendering and the latter is known as client-side HTML rendering.

In server-side rendering, each time the client requires a web page, it must send a request to the server to download the content. Thus, a user browsing a website will normally lead to multiple requests being sent to the server, one request for each web page.

In client-side rendering, the browser will download all the content for the entire website when the user first views the website. The client then renders each required web page within the web browser as the user navigates around the website. Typically, there are only a few requests made to the server.

Server-side rendering and client-side rendering each have its own pros and cons. Thus, you should choose the most appropriate approach for the website or web application that you are creating. For examples, digital commerce or content applications that rely on Search Engine Optimisation or SEO are generally more suited to server-side rendering. Applications such as data dashboard that require faster responsiveness and higher interactivity are more suited to client-side rendering. In server-side rendering, since the presentation tier code runs on the server, it exhibits a stronger notion of backend development. As for client-side rendering, it will certainly fall under frontend development.

JavaScript can be used for both backend development and frontend development. For backend development and frontend development involving server-side rendering web applications, Node.js and its associated frameworks such as Express.js can be used. As for client-side rendering web applications, popular JavaScript frameworks include React, Angular, and Vue. Python can also be used for both backend development and frontend development. But for frontend development, Python is only suitable for creating server-side rendering web applications. Popular Python web development frameworks include Django and Flask.

This module focuses on creating server-side rendering web applications using JavaScript with Express.js and Python with Flask. The subsequent videos in this module we will explain more about each of these two development stacks.

## Video 4: Server-Side Web Application Development with Express.js

In this video, you will learn how to create static content in a server-side rendering web application using Express.js and JavaScript. Let's begin with some basic routing concepts. Routing determines how a web application responds to a client's HTTP request that is sent to a particular endpoint. An endpoint is a combination of a Uniform Resource Identifier, or URI and a specific HTTP request method or verb.

An URI consists of the HTTP protocol specifier, domain name or IP address of the web server and followed by a path within the web application. Let's look at a simple example of an endpoint, GET http://localhost:3000/car. In this example, HTTP is the protocol specifier, localhost:3000 points to the web server running on port 3000 of your local computer and the path is /car. The root path of the web application is simply denoted by a forward slash.

Within an Express.js web application, endpoints are defined as routes. Each route consists of a handler function that is associated with a path without the protocol specifier and server name and a HTTP method. Thus, a handler function is executed when the path is matched with the corresponding HTTP method. The app.METHOD function of Express.js is used to define routing. HANDLER is used to designate a JavaScript function that is executed when a route is matched. The string return value of the function becomes the HTML content displayed in a web browser. Express.jS supports methods that correspond to all HTTP request methods. app.all() is a special routing method that is used to load a handler function at a path for all HTTP request methods. But do take note that for a web application serving HTML content, we typically use only the GET and POST methods. The other methods are used for API endpoints, which will be discussed in a future video.

Let's look at a simple example of routing in Express.js. In this example, there are three routes being defined. The first route is for the root path. The next two routes are for the /car and /book paths. Sending a GET http://localhost:3000/car request from either a web browser or a testing tool such as Postman will display the streamed data returned by the handler function as HTML content. In Express.js, route paths can be strings, string patterns, or regular expressions. For example, the path pattern shown here will match abcd, abbcd, abbbcd, etc. This mechanism provides flexibility to route definition. If you need to define multiple routes for the same path but with different HTTP methods, a more concise syntax of route chaining can be used with the app.route function of Express.js. In this example, we define two endpoints for the same /car route but with two different HTTP methods of GET and POST.

Let's move on to find out how to pass data to a web application using parameters. This is a very useful technique for customising the content generated by a web application. For example, you might define a route/product to display a list of product items. Using this single route, we can pass in the required product category to the web application so that it can render the required content. This is more efficient than defining two separate routes of /car and /book for example.

There are two types of parameters that can be defined in Express.js. The first type is route parameter, which uses named segments in the path to capture the value specified at their respective position in the path. For each value, the key is the name of the route parameter specified in the path. Route parameters are defined using the /:param convention. This example shows the category route parameter defined in the /product route. The second type of parameter is the query string parameter. This type of parameter is appended to the end of the path after the question mark special character using this convention. This example shows the category query string parameter defined in the /product route.

In general, route parameter is preferred if search engine optimisation is important as search engines rank a dynamic path containing query string parameter lower. Do also take note that the data type of parameter values default to string. If you need to manipulate a number, you should perform the required type casting operation. Methods in the response object or res can send response to the client or web browser and terminate the request-response cycle.

A web application normally uses the res.send() method to send back the HTML content as you would have observed in the preceding example codes. res.sendFile() can also be used to send a file such as PDF documents back to the web browser.

Finally, an Express.js web application can handle conversational state using the session middleware. A middleware function is a special function that has access to the request and response objects for performing intermediate processing before the route's handler function is invoked. To save data in the session middleware, you can use the req.session object together with the required property name. A new property defaults to undefined and should be initialised before the first use. Express.js uses a session ID to identify each unique user and this session ID is stored in a cookie. The session ID then is sent back to the server with each request to correctly identify the user. The actual session data is stored on the server.

In this example, a simple counter is stored in the session of each user such that the counter's value is uniquely incremented. Observe that the two browser windows are showing values of different counters. Common data that are stored in the session include login information and shopping cart data. This wraps up our discussion on creating server-side rendering web applications with Express.js.
